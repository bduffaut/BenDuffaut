Students join organizations, browse and rate events, and comment. Admins create events, and
superadmins approve them. I built most of the backend and the database behind it.

## What I built

- **Schema and rules.** A MySQL schema for universities, organizations, memberships, events, ratings and comments. The database itself enforces that no two events overlap at the same place and time, so the rule holds no matter which page writes the event
- **Roles and access.** Student, admin and superadmin sessions, with every page checking the role before it reads or writes anything
- **Event import.** Superadmins can pull in the university's public events feed. The importer parses the XML, geocodes each location with the Google Maps API, and adds the events to the catalog
