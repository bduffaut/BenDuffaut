LLM judges like DeepEval, Ragas and Promptfoo score other models' answers. But who checks the judge?

mtlj changes ("mutates") answers in ways that _should_ lower a score, like dropping a fact or
contradicting the question, and in ways that _shouldn't_, like rewording or padding. Then it uses
statistics to check whether the judge actually notices.

## The engine

I build much of the Python core that every audit runs through.

- **Async judge runner.** Scores every original and mutant several times, with a configurable number of calls in flight on a dedicated thread pool. Each result is written to a JSONL file the moment it finishes, so a run that's killed halfway keeps everything scored so far. One failed call becomes an error row instead of stopping the run. Only a streak of 20 failures, like a revoked API key, aborts it.
- **Data model.** Pydantic models for dataset records and mutants. A mutant carries its full provenance, and its id is a hash of its inputs, so any surprising result can be regenerated exactly and defended.
- **Corpus loader.** Loads the 919-record RAGTruth corpus into one format. Bad lines are skipped and reported with their line number, and the file is checked against its manifest's SHA-256 first, so an edited corpus can't slip into an audit.
- **Adapter contract tests.** One suite every judge adapter must pass: scores in range and never silently clamped, inputs never modified, errors propagated, and parallel calls that never lose or swap results. The async runner depends on those guarantees.

Next up for me: config loading and validation, the `audit run` command, and the machine-readable audit report.
