Every page is prerendered to static HTML at build time from typed content files, checked against
schemas so a typo fails the build instead of breaking a page.

## The server side

The pages are static, but a small Node server (Nitro) runs alongside them.

- **Contact API.** Validated with the same rules as the form, from one module shared by the browser and the server. It rate limits each visitor, refuses oversized bodies before reading them, quietly drops bots with a honeypot, a fill-time check and optional Cloudflare Turnstile, and sends mail over SMTP with Reply-To set to the sender
- **Clear failures.** Every error returns the right status code (422, 429, 502, 503) and a message that tells the visitor what to do next
- **Generated assets.** The sitemap is built from the content, and the social preview image is rendered at build time with a headless browser
- **Operations.** A health check for Docker, and self-hosted Umami analytics proxied through the site's own domain

## How it's served

- A multi-stage Docker build compiles the site, renders the social preview image with a headless browser, and ships a small Node image
- GitHub Actions lints, type checks and tests every push, then publishes the image to GitHub Container Registry
- A home server ([my homelab](/projects/homelab), a repurposed Linux laptop) pulls new images automatically and serves them through a Cloudflare Tunnel, with no open ports and no exposed home IP
- Self-hosted Umami analytics, proxied through the site itself

## The design

Dark surfaces, chamfered panels and a teal signal color, borrowed from the demo app of my dashboard
grid. Animations are CSS-first and turn off for anyone who prefers reduced motion.

The projects section on the home page is a live board running on
[`custom-dashboard-grid`](/projects/dashboard-grid), my own library from npm. Visitors can
customize it, and their board is kept in their browser.
