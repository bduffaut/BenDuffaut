Instead of letting an old laptop sit in a drawer, I wiped it and turned it into a server that runs
around the clock. It has three jobs: it hosts my personal projects, including
[this site](/projects/this-site), it runs a Plex media server that replaced my streaming
subscriptions, and it's the backup target for my computer and my photo library.

## The machine

Ubuntu 26.04 LTS, run headless and managed over SSH. It's tuned to behave like a server rather
than a laptop: closing the lid doesn't suspend it, and Docker and every service come back on their
own after a reboot or a power cut.

Each service is its own Docker Compose stack with a restart policy, a health check, rotated logs
and a memory cap, so one misbehaving container can't take the rest of the box down with it. Dockge
gives me a dashboard over all of the stacks.

## The network

**Nothing is exposed.** My router has zero inbound ports open. Public traffic reaches the server
through a Cloudflare Tunnel instead: `cloudflared` runs in a container and holds outbound
connections to Cloudflare's edge, and Cloudflare routes each public hostname down the tunnel to
the right container on the internal Docker network. TLS terminates at the edge, and my home IP
never appears in DNS.

**Admin access is private.** SSH and the Dockge dashboard are only reachable over Tailscale, a
WireGuard mesh between my own devices. They aren't on the open internet at all, so there's no
login page for anyone else to find.

**DNS and email live at Cloudflare too.** The tunnel creates the DNS records for each site, and
Email Routing forwards mail for my domain to my inbox.

## The services

**Web hosting.** Sites run as hardened containers: a read-only filesystem, a non-root user, no
privilege escalation and a memory limit. Deploys are hands-off. When I push to `main`, GitHub
Actions tests the code and publishes a new image, and a systemd timer on the server pulls it and
swaps the container within two minutes.

**Media.** Plex Media Server organizes my movies and shows and streams them to the TV and my other
devices, so I own the library instead of renting it from a handful of streaming apps.

**Backups.** My desktop and my photos back up to the server's storage, so a dead drive or a lost
phone doesn't mean lost files.

## What it taught me

Running my own infrastructure means I'm the one on call. I learned to think about what
happens when things fail: what restarts on its own, what's exposed and to whom, and where the data
actually lives. It's the same thinking I bring to production code, applied to the whole stack
under it.
